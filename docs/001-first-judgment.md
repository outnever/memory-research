# 001 — 第一份判断：精度是写时的问题，第一个实验测 silent need

> **状态：判断（judgment），不是设计（design）。** 本文不提出完整设计，不含任何测量。
> 它回答 issue #1 的三个问题，并给出一个可以在一周内跑完的第一个实验。
> 没有跑过的东西，文中标为"判断"或"猜测"。

## 0. 结论

**核心难点是有效性（validity），不是检索。** 危险的不是"找不到"，而是"曾经为真、现在不为真，系统却不知道"。charter 列出的四种失败——编造、混淆、过期、丢出处——都不是检索排错了序，而是写记忆时没有把"它在什么条件下成立"一起写下来，读的时候才暴露。

**两条约束不矛盾，但不能同时最大化。** 它们只在"回忆＝把记忆内容塞进 prompt"这个前提下互斥。把三件事分开——存储与携带、谁触发、可读与可执行——可以同时做到"有界且小"。"零成本"做不到；真正要设计的是**把不可避免的那份成本花在哪里**。

**第一个实验不该测检索质量，该测 silent need**：新会话里，当正确做法依赖一条旧事实，agent 会不会意识到、会不会去取、取到后会不会信错。这个分叉决定读路径的形态，而且一周内能跑。

## 1. 核心难点

### 1.1 现有系统解决的是另一个问题

MemGPT 用"虚拟上下文"在窗口和外部存储之间分页，本质是**把上下文管理得更好**；Mem0 做抽取与整合，报告了相对全量上下文的 token 节省，但机制仍是"先取回、再放进 prompt"；Zep 用双时间知识图谱记录事实的有效期；GraphRAG 用社区摘要回答全局问题，索引成本很高。它们都在回答：**怎么在有限的窗口里放进更有用的内容。**

这个仓库问的是另一个问题：**能不能不放进去。** 两者只共享"存储"这一层。把上述系统直接搬过来，等于接受"回忆必然占用上下文"，再优化占用量——那是把约束当成目标函数，而不是边界条件。

（判断）现有系统里最值得偷的是 Zep 的**双时间**建模：把"事实何时为真"（valid time）和"系统何时知道"（transaction time）分开。这是有效性问题的正确形状。但 Zep 仍然把记忆当作文本取回，没有把"取回后先验证"当作默认动作。

### 1.2 四种失败都是写时欠账

- **编造**：存的时候没写"这是猜测还是事实"，取的时候就没有东西可以区分。
- **混淆**：存的时候没写"这是关于哪个 X 的"，取的时候只能靠相似度。
- **过期**：存的时候没写"它在什么条件下失效、被谁取代"，取的时候无法判断。
- **丢出处**：存的时候没留下可复查的地址，取的时候无法验证。

读路径能做的只有"发现"（或去源头重验），但前提是写的时候留下了条件和出处；它不能凭空修复。所以**精度主要是写路径的属性**（判断）。这也是我对现有路线最大的不同意：大家把注意力放在 embedding、rerank、图遍历，而这些只能让"取回相关的东西"更准；它们不能让"取回的东西仍然为真"。

### 1.3 那么表示形式重要吗

重要，但它是二阶问题。表示服务于两件事：写的时候能不能把条件写下来，读的时候能不能廉价地验证。一个能表达"这条事实的失效条件"的普通记录，比一个不能表达条件的漂亮图更有用。**先决定要记什么、带什么条件，再决定用什么存。** 反过来做，就会得到一堆无法判断真假的向量。

## 2. 两条约束

### 2.1 矛盾只在"回忆＝注入"下成立

如果"回忆"的定义是"把记忆文本放进 prompt"，那么：

- 要准 → 要多给证据、上下文、多个候选 → 占更多上下文；
- 要省 → 要少给 → 更容易漏或错。

这是真的矛盾。但这个定义不是必然的。它是当前 RAG / agent-memory 的默认实现，不是问题的定义。

### 2.2 三个分离

**（1）存储与携带分开：给 handle，不给正文。**
记忆保存在上下文之外，进入上下文的只是"地址 + 一行摘要 + 一个验证方式"。agent 需要时再解引用。成本从"一段文档"降到"一个指针"。
这不能免费：指针也要 token；解引用要一次 round trip（延迟）。但它把成本从"每次回忆付全文"变成"每次回忆付指针，只有真的要用才付全文"。

**（2）决定与内容分开：让环境触发，而不是让模型想起来。**
on-demand 检索的真正成本不是查询，是**模型必须先意识到自己缺什么**。charter 已经指出"让 agent 构造好 query 只是转移成本"。更省的形态是：当 agent 碰到某个文件、符号、命令、错误时，环境知道"这里有一条相关记忆"，主动递一个 handle。模型不需要先知道自己不知道。
这仍有成本：误报会占上下文；触发器本身要维护。但它把"注意力成本"换成了"工程成本"，后者可以离线优化。

**（3）可读与可执行分开：有些记忆不该被读。**
一条"这个命令在这里会失败"的记忆，可以变成一条测试、一个 guard、一个 wrapper 脚本。它占 0 个 prompt token，而且它的正确性由执行来保证——错了会红，不会悄悄被信。
（猜测）这是被低估最严重的方向。它把"记忆的准确性"从模型的判断变成环境的断言。它的边界：只适用于可判定的、动作性的记忆；"用户偏好"这类东西无法编译成测试。

### 2.3 残余成本：必须诚实

不存在零成本。任何方案都要付下面至少一项：

- **进入上下文**：token；以及长上下文里 "lost in the middle" 式的注意力衰减（Liu et al., 2023）。
- **不进入上下文**：一次决定——要么模型花注意力决定要不要取（on-demand），要么系统承担误报（proactive）。
- **延迟**：一次检索 + rerank + round trip，可能比 50 个 token 的指针更贵。

| 机制 | 单次回忆的 prompt 成本（粗估，猜测） | 额外延迟 | 准确性由什么保证 |
| --- | --- | --- | --- |
| 全文注入 | 高（数百–数千 token） | 一次检索 | 模型自己判断（弱） |
| handle | 低（约 20–50 token） | 解引用时一次 round trip | 解引用时可带出处/时间 |
| 环境触发 | 0（未命中时） | 触发检查 | 触发器 + 模型 |
| 可执行（测试/guard） | 0 | 运行检查 | 执行（强） |

所以正确的目标不是"零上下文"，而是：**单次回忆的上下文成本有上界；只在可验证的需要上支付；错了能被发现。** 谁能把这三句话变成机制，谁就同时满足了两个约束。

## 3. 第一个实验：silent need

### 3.1 问题

> 在一个新会话里，当任务的正确做法依赖一条上一会话留下的事实，agent 会（a）意识到需要它、（b）去取、（c）取到后正确地用吗？给它一个记忆工具，能拿回"直接告诉它答案"的多少收益，代价是多少上下文？

### 3.2 为什么是它

因为它测的是**所有读路径设计共同的前提**：回忆由谁触发。这个问题有两个显而易见的答案——模型自己调工具，或系统主动注入。charter 已经怀疑前者（query 成本只是转移）。如果实验显示模型自己调工具只能拿回 oracle 收益的一小部分，那么 on-demand 路线就必须让位给系统触发；如果显示它能拿回大部分且 token 很低，那么设计可以简单，精力应该转到写路径和有效性上。**两种结果都会改变下一步，而且成本最低。**

它不测：表示形式、检索算法、写路径质量。这些都被有意固定住，作为后续变量。

### 3.3 设计

**任务集。** 12 个小型、可判定的任务，跑在一个自包含的合成仓库上（一种语言 + 测试套件）。每个任务有且只有一条"隐藏依赖"：一条来自上一会话的事实，缺了它，最自然的做法会失败；有了它，测试通过。例子：

- 依赖必须钉在 `lib==1.4`，因为 1.5 改了 API；
- 部署配置读 `config/app.yaml`，不是 `.env`；
- 某个迁移必须排在另一个之后；
- 某个函数已改名，旧名只是临时别名；
- 某个库因为已知 bug 不能用，必须换掉。

**先筛任务：** 每个任务先跑 A 和 C；只有 A 失败、C 成功，才进入正式任务集。否则丢弃或改写。判定用测试，不用 LLM judge。

**记忆库（手工构造）。** 故意不让 agent 自己写记忆：本实验隔离读路径。库里放三类东西：

1. 每个任务需要的那条正确事实；
2. **近似干扰**：关于相似模块/项目的、看起来对但不对的事实（测混淆）；
3. **已过期事实**：旧值 + 一条更新的正确值（测"信错"）。

**条件（同一模型、同一 prompt 模板、同一仓库快照；每个条件都从同一份快照开始，任务顺序固定）：**

- **A：无记忆。** 下界。
- **B：记忆工具。** 一个 `recall(query)`，在手工库上做简单的混合检索，固定 top-3；system prompt 告诉 agent 有记忆可用。**B 被故意做得慷慨**：如果这样它仍然失败，负结果更强。
- **C：oracle。** 直接把那条正确事实作为一句话注入。上界。

**指标（每个任务、配对比较）：**

- 任务通过率（测试）；
- 记忆调用次数 / 任务；
- 检索命中率（top-3 里有没有正确事实）；
- **silent miss**：任务失败且没有调用记忆；
- **asked-but-missed**：调用了记忆，但 top-3 里没有正确事实；
- **wrong trust**：取到了干扰/过期事实并按它行动（测试失败）；
- 每任务 prompt token（system + 记忆 + 工具结果）、实际耗时。

**主指标：收益捕获率**
`value captured = (B − A) / (C − A)`，要求 `C > A`，且 `C − A` 至少覆盖 6/12 个任务，否则任务集无效。

**预注册的判定规则**（先写死，避免事后解释）：

- 若 `value captured ≥ 0.7`，且额外 token ≤ 任务 prompt 的 5%，且 wrong trust ≤ 1/12 → **模型自触发可用**，下一步转写路径/有效性。
- 若 `value captured ≤ 0.4`，或 silent miss > 1/3 → **必须系统触发**，下一步做触发器实验。
- 中间 → 混合；先看 silent miss 和 wrong trust 哪个是主因。

**最小版本（一个下午）：** 6 个任务，只跑 A 和 B，一个模型，每个任务 1 次。它不足以给出可信的捕获率，但足以回答"silent miss 是不是普遍现象"。如果连这个都做不了，说明任务集本身还没准备好，这本身是信息。

### 3.4 它不回答什么

- **写路径**：库是手工的，所以不测"agent 会不会写错记忆"。
- **表示**：固定成扁平记录 + 简单检索。
- **规模**：12 个任务是方向性的，不做显著性声明。
- **真实 DSH 会话的长尾**：任务是人造的，可能比真实使用更"需要记忆"或更不需要。

### 3.5 为什么不是别的

- **先比表示（向量/图/结构化）**：读接口还没定，表示是下游；现在比，测的是库，不是设计。
- **先做过期/混淆的对抗测试**：结论大概率是"RAG 会信错"，这不新，也不改变架构。把它们作为本实验的第二个测量维度更划算。
- **先做可执行记忆**：最新颖，但它是"解法"。在没测出"需要什么"之前做，容易做一个没有用户的机制。
- **先建完整 benchmark**：本实验的任务集就是 benchmark 的第一版，单独建是重复劳动。

## 4. 对流程与研究方法的直话

1. **PR 不是判断的单位。** 这个 ticket 本身就是例子：你问的是判断，交付物却要走 PR。PR 适合"有 diff 的结果"，判断没有 diff，容易让一个观点看起来像一个结论。建议允许两种产物：`docs/NNN` 的判断（明确写"无测量"）和 PR 的实测结果/代码。或者保留 PR，但强制一个三行头：**我相信什么 / 证据是什么 / 什么会让我改变主意**。

2. **没有任务分布，就没有"精度"。** "recall must be accurate" 在有一个带 ground truth 的任务集之前是不可测的；每个设计都可以在自己的例子上宣称准。第一个实验顺手产出这个任务集，这是它附带的最大资产。

3. **写路径被严重低估。** `questions.md` 里检索/表示占了大头，写路径只有 README 里一行。按第 1 节的论证，精度是写时决定的；写路径至少应该和检索同等重要。建议加三个问题：什么值得写、带什么条件写、如何保证猜测不被当成事实取回。

4. **"漏掉一条记忆代价小"是假设，不是前提。** charter 把它当前提。在 agent 工作里，漏掉可能意味着重复劳动、错误的默认值、或者一个坏掉的构建；代价随任务不对称。它应该被测量，而不是被规定。

5. **"先读 prior art"和"一周内可测"需要更明确的边界。** 前者容易膨胀成综述（你也不想要综述），后者容易被误读成"不许想大问题"。建议：读的时间盒（比如半天），以及明确区分"判断"（可以先于证据，但必须标注）和"设计"（等实验）。`docs/README.md` 原来写的是"没有 001 是故意的"；这句话会挡住判断，也挡住下一步。这次我把 001 明确标成判断而非设计，并把那句话改成"设计仍等证据"。

## 5. 读了什么；哪些是猜测

引用仅用于支撑上面的具体论点，不是综述：

- RAG 的原始形式与"取回再注入"：[Lewis et al., 2020](https://arxiv.org/abs/2005.11401)
- 长上下文中的位置效应（"lost in the middle"）：[Liu et al., 2023](https://arxiv.org/abs/2307.03172)
- 上下文分页：[MemGPT, Packer et al., 2023](https://arxiv.org/abs/2310.08560)
- 抽取/整合式记忆：[Mem0, Chhikara et al., 2025](https://arxiv.org/abs/2504.19413)
- 双时间知识图谱：[Zep, Rasmussen et al., 2025](https://arxiv.org/abs/2501.13956)
- 图摘要式检索：[GraphRAG, Edge et al., 2024](https://arxiv.org/abs/2404.16130)
- 记忆流 + 反思：[Generative Agents, Park et al., 2023](https://arxiv.org/abs/2304.03442)

**判断（无测量支撑）：** 精度主要是写路径问题；现有 agent-memory 系统解决的是窗口内优化而不是"不占上下文"；Zep 的双时间形状是对的。
**猜测（明确未验证）：** 可执行记忆（测试/guard/wrapper）是被低估的方向；环境触发比模型自触发更省注意力。
**没有做的事：** 没有跑任何实验；没有实现原型；没有验证上述引用之外的系统。
